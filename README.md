# GripApprover

Claude Code のツール実行を、ハンドグリップを決められた回数握ることで承認する仕組みです。危険な操作ほど必要な回数が増えます。中身を読まずに Yes を押し続ける承認疲れを、物理的な手間で防ぎます。

筋肉エンジニアの会の LT 用に作りました。

```
Claude Code ──PreToolUse hook──▶ grip_gate.py ──HTTP──▶ grip_daemon.py ◀──BLE── ESP32 ◀── ハンドグリップ
```

| ディレクトリ | 中身 |
|---|---|
| `firmware/` | ESP32 のファームウェア（PlatformIO）。握った累計回数を BLE で通知する |
| `daemon/` | PC 常駐デーモン。ESP32 と常時接続し、hook の問い合わせを握った回数で待たせる |
| `demo/` | 登壇で Claude Code を起動するディレクトリ。`.claude/` に hook と settings がある |

## 必要な回数

| 対象 | 回数 |
|---|---|
| 危険な Bash（`rm -rf`、`git push -f`、`git reset --hard`、`git clean -f`、`sudo`、`DROP TABLE`、`chmod -R 777`、`curl ... \| sh`） | 50 |
| 上記以外の Bash | 10 |
| Edit / Write / MultiEdit / NotebookEdit、MCP ツール | 5 |
| WebFetch | 3 |
| Read / Grep / Glob など | 0（確認しない） |

待ち時間は `min(15 + 回数×3, 110)` 秒です。時間内に握り切れば `allow`、足りなければ `deny` になり、理由が Claude に返ります。デーモンが動いていないときやグリップがつながっていないときは、Claude Code の通常の確認ダイアログ（`ask`）になります。

## ハードウェア

ハンドグリップの左右のハンドルの内側にアルミテープを貼り、握り切ったときに GPIO4 と GND がつながるようにします。

| ESP32 ピン | 接続先 |
|---|---|
| GPIO4 | グリップ片側のアルミテープ |
| GND | グリップ反対側のアルミテープ |
| GPIO25 | アクティブブザー（+） |
| GND | アクティブブザー（−） |
| GPIO2 | 基板上の LED（配線不要） |

- アルミテープは粘着面が電気を通さない製品が多いです。ジャンパーワイヤーの金属ピンをハンドルに当て、上からテープを貼って挟み込みます。
- 電源は単3×4本を VIN へつなぐか、USB モバイルバッテリーを使います。9V 角型電池は電流が足りず不安定になりやすいので使いません。

## 書き込み

```sh
pio run -d firmware -t upload
pio device monitor -d firmware   # 握るたびに grip N と出る
```

## デーモンの起動

```sh
uv run daemon/grip_daemon.py
```

- 依存は `bleak` だけで、`uv run` が自動で入れます。
- BLE を使うには、起動したターミナルアプリに macOS の Bluetooth の許可が必要です。Bluetooth の許可がない環境で試したところ、BLE のスキャンを始めた時点でプロセスが終了コード 134 で落ちました。ダイアログが出ずに落ちるときは「システム設定 → プライバシーとセキュリティ → Bluetooth」を確認してください。
- Claude Code 側で待機を中断しても、デーモンは締め切りまで待ち続けます。リハーサルで中断した直後に次の依頼を出すと、順番待ちのまま時間切れになることがあります。
- `http://127.0.0.1:8766` で待ち受けます。設計時は 8765 番の予定でしたが、手元の別のツールが使っていたため 8766 番にしました。
- 待機中は、ラベル・進捗バー・回数・残り秒数を0.5秒ごとに表示します。登壇時はこのターミナルを映します。

## デモ

```sh
cd demo
claude
```

1. 開始前にデーモンを起動し、「接続しました」と出ていることを確かめる
2. `mkdir -p build` で消す対象のディレクトリを作っておく
3. 「`npm test` を実行して」と頼む → 10回握って承認
4. 「`rm -rf build` を実行して」と頼む → 50回を求められる。途中で力尽きて時間切れになり、`deny` の理由が Claude に返る

「build ディレクトリを消して」のように頼むと、Claude が先に `ls` などを実行して10回ずつ求められることがあります。実行してほしいコマンドをそのまま書いて頼むほうが確実です。

`demo/.claude/settings.json` の `permissions.deny` には、`rm -rf /` などの致命的なコマンドを入れています。hook の `allow` は deny ルールを上書きしないので、握り切ってもこれらは実行されません。

## 注意

- BLE はペアリングなしで接続します。近くの第三者が同じ名前のデバイスを立てると、偽の回数を送れます。
- 承認の判断はすべて PC 側で行います。ESP32 が送るのは握った回数だけです。
