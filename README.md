# GripApprover

Claude Code のツール実行を、ハンドグリップを決められた回数握ることで承認する仕組みです。危険な操作ほど必要な回数が増えます。中身を読まずに Yes を押し続ける承認疲れを、物理的な手間で防ぎます。

筋肉エンジニアの会の LT 用に作りました。

```
Claude Code ──PreToolUse hook──▶ grip_gate.py ──HTTP──▶ メニューバーアプリ ◀──BLE（または USB シリアル）── ESP32 ◀── ハンドグリップ
```

| ディレクトリ | 中身 |
|---|---|
| `firmware/` | ESP32 のファームウェア（PlatformIO）。握るたびに累計回数を BLE と USB シリアルの両方へ出力する |
| `menubar/` | Mac のメニューバーに常駐するアプリ（Rust）。ESP32 とつながり、hook の問い合わせを握った回数で待たせる。メニューからオン・オフを切り替える |
| `demo/` | 登壇で Claude Code を起動するディレクトリ。`.claude/` に hook と settings がある |

## 必要な回数

| 対象 | 回数 |
|---|---|
| 危険な Bash（`rm -rf`、`git push -f`、`git reset --hard`、`git clean -f`、`sudo`、`DROP TABLE`、`chmod -R 777`、`curl ... \| sh`） | 50 |
| 上記以外の Bash | 10 |
| Edit / Write / MultiEdit / NotebookEdit、MCP ツール | 5 |
| WebFetch | 3 |
| Read / Grep / Glob など | 0（確認しない） |

待ち時間は `min(15 + 回数×3, 110)` 秒です。時間内に握り切れば `allow`、足りなければ `deny` になり、理由が Claude に返ります。

- アプリが起動していないときや、メニューでオフにしているときは、hook は何もしません。Claude Code は hook がない場合と同じように動きます。
- オンなのに ESP32 がつながっていないときは、Claude Code の通常の確認ダイアログ（`ask`）になります。

## ハードウェア

ハンドグリップの左右のハンドルの内側にアルミテープを貼り、握り切ったときに GPIO4 と GND がつながるようにします。

| ESP32 ピン | 接続先 |
|---|---|
| GPIO4 | グリップ片側のアルミテープ |
| GND | グリップ反対側のアルミテープ |
| GPIO18 | アクティブブザー（+） |
| GND | アクティブブザー（−） |
| GPIO2 | 基板上の LED（配線不要） |
| VIN | 電池ボックス（赤） |
| GND（VIN の隣） | 電池ボックス（黒） |

GND は基板に複数あり、どれを使っても同じです。ピンの位置は基板の印字で確かめてからつなぎます。

- アルミテープは粘着面が電気を通さない製品が多いです。ジャンパーワイヤーの金属ピンをハンドルに当て、上からテープを貼って挟み込みます。アルミホイルなら両面とも電気を通すので、ピンを包むだけでつながります。
- 接点は、握り切ったときに触れ合うハンドルの内側の面だけに付けます。ハンドル全体に巻くと、手を通して GPIO4 と GND がつながり、握り切っていないのに数えられることがあります。

### 電源

単3電池4本のスイッチ付き電池ボックスを、VIN と GND につなぎます。基板の上で 3.3V に下げて使うので、3V3 ピンにはつながないでください（6V がそのまま ESP32 に入り、壊れます）。

- 使わないときは電池ボックスのスイッチを切ります。電源が入っている間は、握っていなくても電気を使い続けます。
- 書き込みなどで USB をつなぐときは、電池ボックスのスイッチを切ります。両方から同時に電気を入れたときに安全かは確かめていません。
- 電池の代わりに USB で Mac につないでも動きます。その場合は USB シリアルで通信します。

## 書き込み

```sh
pio run -d firmware -t upload
pio device monitor -d firmware   # 握るたびに grip N と出る
```

## メニューバーアプリ

Rust のツール一式（`rustup`）が必要です。

```sh
cd menubar
cargo build --release
./target/release/grip-approver
```

- 起動するとメニューバーに「💪 OFF」が出ます。クリックして「オン」を選ぶと有効になります。
- 表示は「💪 OFF」「💪 ON」「💪 未接続」のどれかで、承認待ちの間は「💪 2/5 12s」のように回数と残り秒数に変わります。
- メニューの「終了」でアプリを終了します。
- 起動したターミナルにも、ラベル・進捗バー・回数・残り秒数を0.5秒ごとに表示します。登壇時はこのターミナルを映せます。
- USB のポート（`/dev/cu.usbserial-*` など）があればシリアルでつなぎ、なければ BLE でデバイス名 `GripApprover` を探してつなぎます。両方を同時には使いません。別のポートを使うときは `GRIP_PORT=/dev/cu.xxx` を付けて起動します。
- BLE を使うには、アプリを起動したターミナルのアプリ（ターミナル.app など）に Bluetooth の利用を許可します。初回に macOS が確認を出します。
- 会議ランプの Chrome 拡張や `pio device monitor` と USB ポートを取り合うので、起動する前に閉じておきます。
- ケーブルを抜いたり電池のスイッチを切ったりすると、待機中の要求は時間切れになります。つなぎ直すと自動で接続し直します。
- Claude Code 側で待機を中断しても、アプリは締め切りまで待ち続けます。リハーサルで中断した直後に次の依頼を出すと、順番待ちのまま時間切れになることがあります。
- `http://127.0.0.1:8766` で待ち受けます。設計時は 8765 番の予定でしたが、手元の別のツールが使っていたため 8766 番にしました。

### Mac 側のシリアルの不具合

ESP32 の USB チップ（CP2102）を macOS 標準のドライバで使うと、どのアプリもポートを開いていない間に ESP32 が出力したデータが、次にポートを開いたときに繰り返し届くことがあります。同じ行や NULL バイトが延々と続く状態です。手元では2回起き、どちらも USB を挿し直すと直りました。

- アプリはオフにしてもポートを閉じません。
- アプリを起動し直すときは、先に USB を挿し直します。

## デモ

```sh
cd demo
mkdir -p build   # rm -rf build で消す対象
claude --setting-sources project,local
```

`--setting-sources project,local` を付けると、ユーザー設定（`~/.claude/settings.json`）の hook や権限の設定を読み込まず、`demo/.claude/settings.json` だけで動きます。普段使いの hook がデモの画面に割り込まないようにするためです。

1. 電池ボックスのスイッチを入れ、メニューバーアプリを起動してオンにし、「💪 ON」になっていることを確かめる
2. 「`pnpm test` を実行して」と頼む → 10回握って承認
3. 「`rm -rf build` を実行して」と頼む → 50回を求められる。途中で力尽きて時間切れになり、`deny` の理由が Claude に返る

「build ディレクトリを消して」のように頼むと、Claude が先に `ls` などを実行して10回ずつ求められることがあります。実行してほしいコマンドをそのまま書いて頼むほうが確実です。

`demo/.claude/settings.json` の `permissions.deny` には、`rm -rf /` などの致命的なコマンドを入れています。hook の `allow` は deny ルールを上書きしないので、握り切ってもこれらは実行されません。

## 注意

- 承認の判断はすべて PC 側で行います。ESP32 が送るのは握った回数だけです。
- アルミテープを厚くすると、軽く握るだけで数えられます。物理的な細工は防げません。
